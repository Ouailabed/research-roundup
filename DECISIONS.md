# Decisions

One line for every choice: what we chose and why.

- AI provider: Groq, because it has a free tier and this project is a trial.
- Models: `openai/gpt-oss-20b` scores every paper and `openai/gpt-oss-120b` writes up the chosen papers, because the free limits are tight.
- Groq's free tier on 31 October 2026 gave each model 1,000 requests a day, 8,000 tokens a minute and 200,000 tokens a day.
- Scoring uses `openai/gpt-oss-20b` at low effort, about 850 tokens a paper. At default effort it took about 1,700, because its hidden reasoning counts. Limits are per model, so when it runs out `openai/gpt-oss-120b` takes over.
- `qwen/qwen3.8-27b` was tried for scoring and dropped. Groq refused about 3 in 10 of its answers, and it scored on a different scale, so mixing it in would have favoured some papers unfairly.
- Scores and full write-ups live in separate tables, because the strong model can do both for the same paper.
- A score only earns a paper a place on the editor's desk. In October 121 of 293 papers scored 9 or 10, so picking by score alone came down to ties, and the two models use the scale differently: `openai/gpt-oss-20b` gave 19 of the first 20 tens. So `openai/gpt-oss-120b` reads every paper scoring 9 or 10 in one sitting, as an editor, and ranks them. Groups of 40 fit inside the limit of 8,000 tokens a minute. It keeps 8 from each group, then ranks the finalists. With no key or no usable answer, the plain scores decide. At the daily limit the editor waits, because its ranking only counts once every group is done, and stopping would waste the calls before it.
- Each issue takes 5 to 8 papers: the top paper of each tag first, so there is a mix where possible, then the rest of the ranking, at most 2 per source. Once chosen, an issue's list is saved and reused, so the same month always gives the same issue.
- The public dashboard is a static page on GitHub Pages, reading one data file. It needs no account or server and never goes to sleep, which Streamlit Community Cloud apps do. `app.py` stays for running locally.
- An issue is never chosen from part of a month: it waits until the month's papers are scored. It allows 5 left over, because a paper can keep failing the checks, and that shouldn't hold up an issue for ever.
- Any past month with no finished issue gets built by whichever job comes next. A month needs both a saved list and a page, so a run that stopped halfway is finished later.
- The prompt holds the IMF's full list of 43 advanced economies, from Table B of the April 2026 World Economic Outlook, not examples. With examples, the model called Korea emerging and Chile advanced, and tagged Italy EM. The list changes over time: Bulgaria joined when it took the euro in 2026.
- A national programme or dataset names its country, so Medicare or SIPP means the US. A paper's publisher doesn't, because a Fed working paper can be about anywhere.
- A second look runs when a tag clashes with the places a paper names. The model decides, not the code, because the check can be wrong: "American Indians" reads as India.
- `python -m src.main check` compares each summary's numbers with its abstract. It can't tell rounding from invention, so it lists them for a person. Of 604 summaries it flagged 6, and all 6 were rounding or simple sums.
- Tag checks use blind AI readers and say so. They were given only titles and abstracts, never the model's tags. The results file keeps the model's tag at the time, so the figure can be rechecked after tags change.
- `timer.yml` was built as a stand-in for cron but isn't running. Claude's permission check refused to start a job that keeps rescheduling itself, so that stays the owner's call.
- A catch-up job scores what's left and builds what's ready. Groq's daily allowance refills steadily, at about 2.3 tokens a second per model, not all at once. Without this job, a run that hit the limit would wait a week to carry on. With nothing to do it changes nothing.
- GitHub's cron can't be relied on alone. On 1 November the 06:30 catch-up and the 07:00 monthly run never came, though every manual run worked, and the first scheduled run fired at 17:56, about 5 hours late. Other people report the same with no confirmed fix. So the jobs sit on quiet minutes, which GitHub's docs advise, and cron stays as one trigger of several.
- Every job that writes the database checks out `main`, not the commit it was queued with. A run that waited its turn would otherwise start from an old database and then fail to merge it, because git can't merge a binary file. GitHub keeps only one waiting run per group, so a queued run can also be replaced by a newer one.
- A crash partway through a job still saves what it finished, because the save step runs anyway. Scores are written one paper at a time, so nothing done before the crash is lost.
- A paper that keeps failing its write-up leaves that issue, so it can't block the month for ever. If fewer than 5 papers remain, the month is chosen again.
- While work is left, the catch-up job waits 2 hours and starts its own next run, because a manual start always works. A run that makes no progress stops the chain, so it can't loop for ever.
- The catch-up job also collects if no run has for a week, so a skipped weekly run costs a few days rather than a whole week.
- Python 3.14 on the laptop, in GitHub Actions and on Streamlit Community Cloud, so all three behave the same.
- Feeds and official APIs come first, because they are stable and allowed. Scraping is a last resort.
- G10 can mean the G10 countries or the G10 currencies, so we cover both. That adds the Reserve Bank of Australia, the Reserve Bank of New Zealand and Norges Bank.
- IMF Working Papers come through Crossref (ISSN 1018-5941), because the IMF feed answered 403 to a script on 31 October 2026.
- Routes are tried in this order: the publisher's own feed, Crossref or DataCite, then RePEc IDEAS. Each source's notes in `config/sources.yaml` say why it uses its route.
- RePEc IDEAS is the fallback for most central banks, because it gives authors, abstracts and dates in the same fields for every bank, and its robots.txt allows scripts.
- BIS abstracts come from each paper's page, because the feed often gives only the first sentence.
- The Reserve Bank of New Zealand is not covered. Its site answers 403 to scripts, RePEc stops in 2024, and we never disguise the script as a browser.
- Papers with no abstract stay in the database but are not analysed, as Yasmine's note on paywalls allows.
- A paper belongs to the month we first saw it, because published dates are unreliable. The backfill is the one exception: it uses the best date the source gives. A month becomes its first day. A year alone becomes 1 January, so those papers can't enter a backfilled issue, and we never guess a month.
- NBER dates come from Crossref (prefix 10.3386), because the feed has none. The backfill reads the JSON behind NBER's public paper list, which robots.txt allows, because Crossref has no NBER abstracts.
- That NBER list cuts abstracts at about 300 characters, which we missed at first: the AI scored 217 papers from cut text. Each paper's own page has the full abstract, so the backfill now reads it. On 1 November 2026 we repaired 267 saved papers this way and scored those 217 again. 41 of them changed tag and 89 moved by 2 or more points, so the cut text had a real effect.
- The health report now warns when more than 1 in 5 of a source's abstracts are under 400 characters and stop mid-sentence, which is how a shortened feed shows itself. Length matters as well, because some full abstracts just lack a final full stop. This check would have caught the NBER problem on day one.
- Text goes through `ftfy`, because some series on RePEc store it with the wrong encoding, which turns ’ into â€™. Abstracts lose the word Abstract at the start and any JEL codes at the end, because neither tells the AI anything about the paper.
- Items that aren't research are dropped by their title: Front Matter, Recent Referees, Comments and Discussion and the like. They all had no abstract, so they made the journals look worse covered than they are.
- JPE abstracts come from RePEc IDEAS, at an address built from the DOI, because OpenAlex has few of them. The paper keeps its OpenAlex date and DOI. RePEc gives a JPE paper only a year.
- 12 more European central banks come through RePEc IDEAS, because the brief says European national central banks and coverage is marked: Czech Republic, Hungary, Greece, Latvia, Lithuania, Estonia, Slovakia, Croatia, Iceland, Luxembourg, Cyprus and Ukraine. A new source's first papers are dated by the source, not by the day we added it, so they don't all land in one month.
- Malta stays out because its RePEc series stops in 2023. We found no RePEc series for Slovenia, Bulgaria, Romania or Serbia.
- The public site merges near-duplicate topics when it publishes, such as labor and labour, and its filter lists only topics used 3 times or more. The saved data keeps what the AI wrote.
- The weekly and monthly jobs share a GitHub concurrency group, because both write the database and git can't merge a binary file. The monthly job scores anything left over before it builds, so an issue is chosen from the whole month.
- Two papers from different sources count as the same if their titles are more than 0.9 alike. The one with the longest abstract is kept. Same-source papers are never merged, because BPEA reuses titles like Comments and Discussion.
